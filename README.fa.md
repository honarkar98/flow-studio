# استودیوی فلو API

یک وب‌اپ محلی و مستقل برای ساخت و اجرای فلوهای HTTP از روی Swagger/OpenAPI. موتور، ذخیره‌سازی و رابط آن به CLM وابسته نیستند؛ فلو قرارداد v2 فقط یک نمونهٔ قابل‌ویرایش است.

برای همکاری یا شروع در یک رایانهٔ دیگر، از [`init`](init) شروع کنید. طراحی فعلی در [`design.md`](design.md)، تصمیم‌های این جلسه در [`docs/decisions.md`](docs/decisions.md)، روش کار مشترک در [`docs/collaboration.md`](docs/collaboration.md) و دروازهٔ انتشار عمومی در [`docs/publication-security.md`](docs/publication-security.md) ثبت شده‌اند.

## راه‌اندازی

از پوشهٔ همین پروژه:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m studio --host 127.0.0.1 --port 8765 --db data/studio.sqlite3
```

سپس [http://127.0.0.1:8765/](http://127.0.0.1:8765/) را باز کنید. برنامه فقط روی loopback اجرا می‌شود. آدرس پایهٔ API مقصد برای هر پروژه جداگانه تعریف می‌شود؛ برای backend محلی CLM مقدار `http://127.0.0.1:8000` است.

## کار با برنامه

1. پروژه‌ای با نام و آدرس پایهٔ API بسازید.
2. فایل YAML/JSON Swagger را انتخاب کنید، متن آن را بچسبانید، یا URL schema را بدهید. Swagger 2.0 و OpenAPI 3.x پشتیبانی می‌شوند.
3. فلو بسازید و endpointها را از کاتالوگ به آن اضافه کنید. در نمای «فهرست» گام‌ها را سریع ویرایش و مرتب کنید. در نمای «دیاگرام»، از ابزار شناور «افزودن گام» نوع گام یا Endpoint را جستجو کنید، روی آن بزنید یا آن را روی بوم رها کنید. کارت‌ها را با گرفتن سربرگ جابه‌جا کنید و با کشیدن فضای خالی بوم پیمایش کنید. دکمهٔ «تمام‌صفحه» فضای کار را گسترش می‌دهد؛ برای خروج، همان دکمه یا Esc را بزنید. تنظیمات گام فقط با دکمهٔ «تنظیمات» همان کارت باز می‌شود. راهنمای چهارمرحله‌ای بالای صفحه وضعیت شروع کار را نشان می‌دهد.
4. متغیرها را در بخش متغیرها تعریف کنید. مقدار می‌تواند متن یا JSON باشد؛ برای مقدارهای حساس گزینهٔ «حساس» را فعال کنید.
5. در مسیر، query، header و body از `{{name}}` استفاده کنید. در مسیر URL، `{name}` هم پذیرفته می‌شود. جای‌گذاری دقیق `"{{name}}"` نوع JSON مقدار را نگه می‌دارد.
6. در ویرایش گام، از فرم «ورودی درخواست» برای اتصال متغیر یا مقدار ثابت به Body، Query یا Header استفاده کنید. در فرم «ذخیرهٔ فیلد پاسخ»، نام متغیر و مسیر پاسخ را وارد کنید؛ برای نمونه `results[0].id`. فرم «بررسی پاسخ» نیز شرط برابری می‌سازد. تمام این تنظیم‌ها در بخش «ویرایش پیشرفتهٔ JSON» قابل مشاهده و ویرایش‌اند. اگر فیلد یا عضو آرایه پیدا نشود، گام خطا می‌دهد و مقدار قبلی متغیر تغییر نمی‌کند.
7. با «ایجاد اجرای جدید» از هر گام دلخواه شروع کنید. برای ادامهٔ اجرای قبلی، آن را از فهرست اجراها انتخاب و «اجرا / ادامه» را بزنید. در توقف دستی، مقدارهایی مثل OTP را وارد کنید. متغیرهای قبلی بعد از بستن و بازکردن برنامه حفظ می‌شوند.
8. تاریخچهٔ پایین صفحه URL کامل، روش، JSON درخواست و پاسخ، کد وضعیت، زمان و خطای **هر تلاش** را به ترتیب نشان می‌دهد. این شامل پاسخ 401، درخواست تازه‌سازی توکن و تلاش مجدد هم هست. مقدارهای حساس پیش‌فرض پوشیده‌اند و با گزینهٔ «نمایش داده‌های حساس» قابل مشاهده‌اند.

### اتصال‌ها و اجرای شاخه‌ها

در دیاگرام، خروجی کارت را روی ورودی یا بدنهٔ کارت مقصد بکشید و رها کنید. رهاکردن خط روی فضای خالی، فهرست افزودن گام را باز می‌کند و گام انتخاب‌شده را به همان خروجی وصل می‌کند. روش کلیکی هم در دسترس است: خروجی را انتخاب کنید و سپس ورودی دایره‌ای مقصد را بزنید. مقصد فعلی روی هر خروجی نوشته شده است. برای حذف اتصال، روی خود خط بزنید و «حذف اتصال» را انتخاب کنید، یا کلید Delete را بزنید؛ دکمهٔ × کنار خروجی نیز همین کار را انجام می‌دهد. اتصال و قطع اتصال همان لحظه ذخیره می‌شود. Esc اتصال در حال ساخت را لغو می‌کند. حذف اتصال عادی به معنی پایان فلو از آن خروجی است؛ حذف مسیر خطا باعث توقف اجرا در زمان خطا می‌شود.

رنگ سربرگ و چیپ هر گام را در «تنظیمات» آن از میان اصلی، موفقیت، هشدار، خطر و ثانویه انتخاب کنید. رنگ همراه فلو ذخیره می‌شود. چیپ‌های ورودی روی کارت، ویرایشگر همان ورودی را باز می‌کنند. در بخش «ورودی درخواست» می‌توانید هر فیلد Body، Query یا Header را ویرایش یا حذف کنید و مقدار متغیرهای به‌کاررفته را تغییر دهید؛ سپس گام را ذخیره کنید.

چیدمان پیش‌فرض گام‌ها در یک مسیر پیوسته از راست به چپ است. برای فلوهای بلند، از فهرست گام‌های سایدبار یا دکمه‌های «قبلی/بعدی» بالای بوم استفاده کنید. خود بوم افقی پیمایش می‌شود و عرض صفحهٔ اصلی به ۱۴۸۰ پیکسل محدود است. سایدبار پروژه، Swagger، کاتالوگ endpointها و دسترسی سریع به دو نما و بخش اجرا را در خود دارد.

گام «شرط» دو مسیر بله و خیر دارد و می‌تواند مقدار متغیر را با عملگرهای برابری، وجود، شامل شدن و مقایسه بررسی کند. گام «حلقه» روی اعضای یک متغیر آرایه‌ای می‌چرخد، هر عضو و شمارهٔ آن را در متغیرهای دلخواه می‌گذارد، و پس از پایان به مسیر «پایان» می‌رود. برای تکرار بدنه، آخرین گام بدنه را به کارت حلقه وصل کنید. وضعیت حلقه همراه اجرا ذخیره می‌شود تا ادامه از نقطهٔ توقف ممکن باشد.

اگر هنگام اجرا متغیری لازم باشد و مقدار نداشته باشد، پنجرهٔ ورود همان متغیر باز می‌شود. ورودی توقف دستی مثل OTP نیز در پنجره دریافت می‌شود. کنار هر درخواست در تاریخچه و هر گام HTTP در دیاگرام، نمایش یا کپی دستور cURL در دسترس است. cURL همیشه URL، هدرها، بدنه و فایل‌های واقعی همان درخواست را بدون پوشاندن مقدارها نشان می‌دهد؛ تاریخچه همچنان مقدارهای حساس را تا زمان فعال‌کردن «نمایش داده‌های حساس» می‌پوشاند. دستور کپی‌شده را می‌توان مستقیم در ترمینال اجرا کرد. بدنهٔ پاسخ و جزئیات خطا در تاریخچه باقی می‌مانند.

وارد کردن نسخهٔ جدید schema فقط کاتالوگ را به‌روزرسانی می‌کند. endpoint حذف‌شده در کاتالوگ با حالت «غایب» می‌ماند؛ فلو، تنظیم گام‌ها، متغیرها و تاریخچه پاک نمی‌شوند. هنگام اجرای دوبارهٔ گامی که پیش‌تر POST موفق داشته است، تأیید صریح لازم است.

## ساختار یک گام

```json
{
  "name": "ایجاد سفارش",
  "kind": "http",
  "method": "POST",
  "path": "/orders/",
  "headers": {"Authorization": "Bearer {{access_token}}"},
  "body": {"item_id": "{{item_id}}"},
  "captures": [{"name": "order_id", "path": "id"}],
  "assertions": [{"path": "status", "equals": "created"}],
  "refresh_on_401": true
}
```

برای تازه‌سازی توکن، در تنظیم پروژه یک درخواست HTTP با `method`، `path`، `body` و `captures` تعریف کنید. این تنظیم عمومی است و به endpoint خاصی وابسته نیست. گام‌های `manual` با `manual_variables` ورودی می‌گیرند. بدنهٔ `json` و `multipart` پشتیبانی می‌شود؛ برای multipart می‌توان فایل را در مرورگر انتخاب کرد یا نام فیلد و مسیر فایل محلی را در `files` نوشت. فایل انتخاب‌شده در پوشهٔ `data/uploads` با دسترسی محدود کپی می‌شود.

## نمونهٔ CLM v2

در پروژه‌ای با URL پایهٔ `http://127.0.0.1:8000` دکمهٔ «افزودن نمونهٔ CLM v2» را بزنید. نمونه از ارسال OTP تا وضعیت `signing` دارای ۱۲ گام است و مانند هر فلوی دیگری ویرایش می‌شود. هر همکار schema و دادهٔ آزمایشی خود را در پایگاه دادهٔ محلی خودش وارد می‌کند.

قبل از اجرا این متغیرها را مقداردهی کنید:

| متغیر | کاربرد |
|---|---|
| `mobile` | شمارهٔ موبایل حساب آزمایشی |
| `national_id` | کد ملی همان حساب؛ بهتر است حساس ثبت شود |
| `address` | نمونهٔ آدرس در metadata قرارداد |
| `contract_title` | عنوان قرارداد؛ مقدار نمونه از پیش وجود دارد |
| `contract_content` | سند TipTap و HTML؛ مقدار نمونه از پیش وجود دارد |
| `end_date` | تاریخ پایان با قالب `YYYY-MM-DD`؛ مقدار نمونه از پیش وجود دارد |
| `signer_user_id` | شناسهٔ عددی کاربر امضاکننده، متفاوت از حساب ورود |

OTP در گام دوم به‌صورت دستی خواسته می‌شود. توکن‌ها، شناسهٔ کاربر، اولین `tenant_id` و `contract_id` از پاسخ‌ها ذخیره می‌شوند. فلو فرض می‌کند حساب واردشده مجوز ساخت و ارسال قرارداد در اولین tenant را دارد و به‌عنوان تأییدکننده ثبت می‌شود. در صورت نبود tenant یا پیش‌نیازهای امضا، همان پاسخ خطا در تاریخچه نشان داده می‌شود و می‌توانید داده‌ها یا گام را اصلاح و از نقطهٔ لازم ادامه دهید.

## داده و آزمون

اطلاعات در `data/studio.sqlite3` ذخیره می‌شود؛ فایل با دسترسی `0600` ساخته می‌شود. تاریخچهٔ خام شامل درخواست‌ها، پاسخ‌ها و توکن‌ها است و باید فقط روی دستگاه مورد اعتماد نگه‌داری شود. حذف فلو، تاریخچهٔ اجراهای آن را هم حذف می‌کند.

```bash
python3 -m unittest discover -s tests -v
```

آزمون‌ها شامل parse و به‌روزرسانی schema، نگاشت متغیرها، توقف OTP و ادامه پس از راه‌اندازی دوباره، retry، تازه‌سازی توکن، تاریخچهٔ پوشیده، API وب و یک فلو کامل عمومی با transport شبیه‌سازی‌شده هستند. آزمون واقعی CLM به حساب آزمایشی، OTP معتبر، tenant دارای مجوز و `signer_user_id` موجود نیاز دارد.
