# ممیزی و دروازهٔ انتشار عمومی

آخرین بررسی: ۲۰۲۶-۱۰-۱۷. این گزارش برای **همین مخزن Flow Studio** است؛ مخزن‌های backend و frontend CLM را پوشش نمی‌دهد.

## یافته‌های بررسی

- فایل‌های آمادهٔ انتشار و ۴۰ blob تاریخچهٔ Git برای الگوهای رایج کلید خصوصی، توکن سرویس، JWT، ایمیل، موبایل و کد ملی بررسی شدند. **کلید خصوصی، توکن با پیشوند شناخته‌شده یا JWT واقعی در این جست‌وجو پیدا نشد.** جست‌وجوی الگویی تضمین نبود همهٔ انواع راز نیست.
- در تاریخچهٔ Git هیچ فایل DB، `.env`، کلید خصوصی یا پوشهٔ `data/` ثبت نشده است. فایل `data/studio.sqlite3` روی این دستگاه وجود دارد، حدود ۴٫۸ مگابایت است و Git آن را نادیده می‌گیرد. این فایل ممکن است حاوی هویت، OTP، توکن و تاریخچهٔ خام باشد؛ **آن را منتشر نکنید**.
- فرادادهٔ commitهای قدیمیِ محلی از نشانی ایمیل سازمانی استفاده می‌کند. push کردن آن تاریخچه آن نشانی را نیز عمومی می‌کند. شاخهٔ عمومی باید از commit ریشهٔ تازه با نشانی `noreply` حساب GitHub شروع شود.
- در فایل‌های فعلی، موبایل و شناسهٔ ملی عددی تست با برچسب‌های آشکارا ساختگی جایگزین شدند. بااین‌حال commitهای قدیمی شامل یک شناسهٔ ملی ۱۰رقمی با رقم کنترل معتبر و شماره‌های شبیه موبایل هستند. واقعی یا ساختگی‌بودن آن شناسه هنوز تأیید نشده است. پاک‌کردن فقط فایل فعلی برای رفع ریسک تاریخچه کافی نیست. **هیچ‌یک از commitهای قدیمی را عمومی push نکنید.**
- `.gitignore` علاوه بر `data/`، محیط مجازی و کش Python، فایل‌های محیطی، پایگاه داده، کلید خصوصی، لاگ و HAR را نادیده می‌گیرد. `.gitignore` فایل قبلاً commit‌شده را از تاریخچه پاک نمی‌کند.
- README و کد شامل آدرس loopback و مسیر endpointهای نمونه‌اند؛ این‌ها credential نیستند. preset CLM از جای‌نگهدارهای متغیر استفاده می‌کند و مقدار حساب واقعی در آن نیست.

## دروازهٔ قبل از GitHub

1. فقط از تاریخچهٔ عمومیِ آغازشده با snapshot پاک ادامه دهید. commitهای قدیمی محلی را merge، cherry-pick یا push نکنید. اگر زمانی لازم شد آن تاریخچه منتشر شود، منشأ fixture هویتی و مجازبودن انتشار ایمیل نویسنده را ابتدا بررسی کنید.
2. با `git status --short --ignored` و `git ls-files` کنترل کنید فایل محلی یا خروجی اجرا staged نشده باشد. `git add -f data/` و commit کردن خروجی API ممنوع است.
3. diff کامل و محتوای staged را از نظر توکن، URL حاوی query حساس، هدر Authorization، OTP، شمارهٔ هویتی، فایل کلید و response واقعی مرور کنید. برای تست‌ها فقط دادهٔ ساختگی و برچسب‌خورده بگذارید.
4. تست‌ها و `git diff --check` را اجرا کنید. پیش از push، `git log --format='%ae %ce'` و `git rev-list --count main` را بررسی کنید تا فقط تاریخچهٔ پاک و هویت `noreply` منتشر شود.

## رفتار امنیتی برنامه

برنامه احراز هویت داخلی ندارد و فقط برای loopback است. گزینهٔ `reveal=1` و مدال cURL مقدارهای واقعی را عمداً نشان می‌دهند؛ از اسکرین‌شات، کپی ترمینال و گزارش خطا حاوی این مقادیر در issue یا pull request عمومی استفاده نکنید. دیتابیس محلی برای همکاری همگام‌سازی نمی‌شود؛ هر همکار دادهٔ آزمایشی خودش را می‌سازد.
