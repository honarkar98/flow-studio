# همکاری دو نفره روی Flow Studio

## شروع هر نفر

1. `init` و `design.md` را بخوانید و `git status --short` را اجرا کنید. این پوشه مخزن مستقل است؛ کد CLM در مخزن‌های دیگر قرار دارد.
2. محیط مجازی و پایگاه دادهٔ محلی خودتان را بسازید. فایل‌های `data/`، `.venv/` و `.env*` را میان همکاران جابه‌جا یا commit نکنید. برای دادهٔ مشترک از fixture ساختگی و بدون هویت واقعی استفاده کنید.
3. اگر دو نفر روی یک دستگاه کار می‌کنند، برای نفر دوم پورت و مسیر DB جدا بگذارید، مثلاً `--port 8766 --db data/friend.sqlite3`.

## تقسیم کار و ادغام

- برای هر تغییر شاخهٔ کوتاه و موضوعی از `main` عمومی بسازید؛ پیش از شروع، وضعیت شاخه و تغییرات نیمه‌تمام را با هم هماهنگ کنید. تاریخچهٔ محلی قدیمی پیش از انتشار پاک‌سازی نشده و نباید به remote فرستاده شود.
- مالکیت فایل‌ها را برای هر کار مشخص کنید. `web/app.js` و `web/diagram.js` در ویرایش دیاگرام به هم وابسته‌اند؛ دو نفر هم‌زمان همان قسمت‌ها را تغییر ندهند. تغییر API داخلی باید با تغییر مصرف‌کنندهٔ وب و تست همان رفتار هماهنگ شود.
- تغییر را در commitهای موضوعی نگه دارید؛ تغییرات کاریِ نفر دیگر را پاک، stash یا بازنویسی نکنید. پیش از ادغام، diff را مرور و تعارض را با توجه به `design.md` حل کنید.
- در review، عمومی‌ماندن موتور، حفظ فلو و متغیر هنگام import مجدد، امکان ادامهٔ اجرا، نمایش تمام تلاش‌ها و رفتار شاخه/حلقه را بررسی کنید.

## تعریف «آمادهٔ ادغام»

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q studio
git diff --check
git status --short
```

تغییرهای رابط را در مرورگر با **DB آزمایشی جدا** بررسی کنید؛ ایجاد نمونه یا اجرا روی دادهٔ واقعی کاربر، تست UI نیست. برای باگ اجرا، یک تست رفتاری معنادار اضافه کنید. اگر رفتار محصول تغییر کرد، `design.md` و `docs/decisions.md` را هم به‌روز کنید. پیش از هر push عمومی، چک‌لیست `docs/publication-security.md` را انجام دهید.
